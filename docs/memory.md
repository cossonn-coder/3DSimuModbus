## Modbus

| Date | Décision |
|---|---|
| 2026-07 | **Deux lignes d'I/O Scanner** : lecture FC3 sur zone `ret`, écriture FC16 sur zone `cmd`. Pas de ligne combinée FC23 en V1. |
| 2026-07 | `%MWn` = holding register d'adresse protocole `n`. Aucun décalage. |
| 2026-07 | Zones à base configurable : `cmd` base %MW100 (1 mot), `ret` base %MW200 (2 mots). Adresses relatives `{zone, word, bit}` dans le JSON. |
| 2026-07 | Heartbeat : mot 0 zone `ret`, +1 toutes les 100 ms, rollover 16 bits libre. |
| 2026-07 | Tout en 16 bits en V1 (pas de sujet d'ordre de mots). TOR packés 16/mot. |
| 2026-07-14 | **FluentModbus 5.3.2 figé** (POC D-001 concluant). Trois règles imposées à `ModbusServer` : (1) déclarer l'unité du pivot via `server.AddUnit(unit_id)` — le défaut ne sert que l'unit 0 et ferme la connexion sinon ; (2) accéder au buffer par `server.GetHoldingRegisters(unit_id)` **toujours via `Get/SetBigEndian<T>`** (buffer natif little-endian ≠ fil Modbus big-endian, sinon octets inversés côté M580/pymodbus) ; (3) l'accès buffer se fait dans une méthode **synchrone** (un `Span<short>` ne peut pas vivre dans du code `async`). Latence commande→retour mesurée = **1 tick** (conforme Arch A). |

## Thread-safety (pattern imposé)

| Date | Décision |
|---|---|
| 2026-07 | Datastore = objet C# pur (`ushort[]` + verrou), zéro dépendance Godot. Thread serveur Modbus ne touche jamais le scene tree. Simulation : snapshot des commandes en début de tick physique, publication des retours en fin de tick. |
| 2026-07-14 | **Arch A actée** (sprint 1, `/conception`) : le `ModbusDataStore` est la **source de vérité** ; le buffer interne de FluentModbus est un détail **privé** de `ModbusServer`, recopié ↔ datastore **à chaque tick physique** sous `server.Lock` (pull `cmd` en début de tick, push `ret` en fin). Le thread serveur ne touche **ni** le scene tree **ni** le datastore : seul le thread physique accède au datastore. Datastore et FluentModbus restent découplés (repli mini-serveur D-001 = une seule classe à réécrire). À réviser **uniquement** si le POC D-001 révèle un vrai problème de latence/contention. |
| 2026-07-15 | **Brique 4 scindée en 4a/4b** (archi `/conception`) : 4a = heartbeat + vérins (S11/S12/S21/S22) + retour convoyeur (KM1_AUX) → porte **les 4 scénarios pytest full-chain** ; 4b = palettes/accumulation/présence B1/B2 (isole l'incertitude du modèle d'accumulation circulaire). Cinématique = **petits modèles purs composés** (`CylinderState`, `ConveyorState`, puis `PalletSet`), `dt` injecté, zéro Godot, testables isolément. L'inversion mi-course du vérin est gérée par le clamp (aucune branche dédiée). |
| 2026-07-15 | **Brique 4b — modèle d'accumulation acté** (point dur levé sans dette). `PalletSet` (modèle pur) : rotation, blocage, accumulation, présence. Deux formulations clés : (1) **espace « sens de marche »** — repère interne où avancer = angle croissant ; pour `cw`, réflexion `phi=360−angle` (involution, préserve les distances), d'où **un seul chemin de code** forward-only et le sens du pivot honoré aux frontières ; (2) **accumulation en `mod 360`** — contrainte `(phi_devant−phi_ici) mod 360 ≥ min_gap`, qui **efface la couture 0°/360°** (pas de tri) et rend un vérin engagé équivalent à **un angle bloqué de plus** (obstacle fixe). Résolution par **relaxation itérative** (`count` passes, cibles décroissantes → convergence). Rotation des palettes pilotée par **`Conveyor.IsRunning` (KM1_AUX)**, pas la commande brute ; vitesse = `KM1.speed_deg_per_s`. **D-008 non créée** (aucune simplification). D-002/D-003 inchangées. `PivotModel.Kinematics` parsé en additif (optionnel au Load, obligatoire à l'usage). |
| 2026-07-15 | **Params machine tirés du pivot** (extension additive `PivotModel`, D-d) : `Component.Params` (sac générique `double`) + `GetParam`, et `HeartbeatPeriodMs` (cadence tick, `heartbeat.period_ms`, défaut 100). Le pivot JSON **n'a pas changé** (tout y était depuis la Phase 0). `Signal.WriteBit` ajouté (symétrique de `ReadBit`). Hôte headless **`SimHost`** (`runtime/simhost/`, console .NET pure) débloque pytest sans Godot : boucle `PullCommands → sim.Tick → PushReturns`, patron du futur `_PhysicsProcess`. |
| 2026-07-15 | **Sprint 2 — cinématique visuelle livrée et validée** (l'ex-« sprint 3 », renuméroté). `CarrouselScene` est devenue **hôte Modbus vivant** : `_PhysicsProcess` rejoue `StepSim` (= `PullCommands → sim.Tick → PushReturns`, patron `SimHost`) puis `ApplyToScene`. **Boucle à pas FIXE** (accumulateur) tranchée : `Tick` reçoit toujours `dt = periodS` (100 ms → heartbeat 10 Hz exact, déterministe), découplé du 60 Hz du moteur ; `ApplyToScene` chaque frame. Divergence assumée avec `SimHost` (`dt` réel) — `SimHost` **non modifié**. **Garde-fous heartbeat** : `run/low_processor_mode=false` versionné dans `project.godot` + anti-spirale (clamp `accumulator ≤ MaxCatchup·periodS` **et** guard `ticks < MaxCatchup`, `MaxCatchup=5`). **`[Export] bool BindLoopback`** (défaut `Any` = M580 distant ; `true` = loopback test local). `server.Start()` en `_Ready`, `Dispose()` en `_ExitTree`. **`ApplyToScene` = snap 10 Hz** (recopie directe, pas d'interpolation, D-d) : tiges en translation +Y (`restY + Position·stroke`), palettes via **le même `OnCircle`** que la brique 5 (repère CCW garanti) ; refs `_rod1/_rod2/_pallets[]` **capturées au build** (zéro `GetNode`/frame, routage explicite par `id` pivot). **Pivot inchangé** (tout y était depuis la Phase 0). **D-010 soldée** (smoke headless `smoke_anim.ps1` + validation visuelle Nico). Dettes nées : D-011 (duplication `StepSim`↔`SimHost`), D-012 (throttling fenêtre non-focus), D-013 (échec `server.Start()` silencieux si 502 occupé). |
| 2026-07-15 | **Cinématique visuelle (sprint 3) — plan de branchement acté** (pas encore implémenté). `_PhysicsProcess(delta)` rejoue **les 3 mêmes appels que `SimHost`** (`PullCommands → sim.Tick(store, delta) → PushReturns`), puis un `ApplyToScene()` **lit** l'état exposé en lecture seule par la sim et l'écrit sur les nœuds nommés : `Pallets.AnglesDeg[i]` → `OnCircle(...)` (même repère que la brique 5), `Cylinder{1,2}.Position` (0..1) → translation de `rod` de `Position·stroke` sur Y. Le scene tree n'est touché **que** dans `_PhysicsProcess` (thread principal Godot) ; le serveur reste sur son thread, ne touchant que le datastore sous `server.Lock` (Arch A, rien de neuf). **Point de design à trancher au sprint 3** : cadence `_PhysicsProcess` (60 Hz par défaut) ≠ cadence tick sim (`period_ms` = 100 ms → heartbeat 10 Hz). Reco : **découpler** (rendre à 60 Hz, accumuler `delta` et n'appeler `Tick` que tous les `period_ms`) pour garder le heartbeat à 10 Hz sans saccade visuelle. |
